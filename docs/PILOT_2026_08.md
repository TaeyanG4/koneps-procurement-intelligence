## 8. Pagination 안정성 감사 (Pagination Integrity)

- **질문**: 1-day 및 1-month 수집에서 발견된 중복 행이 API 오프셋 밀림(Page Overlap) 때문인가, 아니면 원천 데이터 자체의 중복인가?
- **검증 방법**: 연속 동일 레코드의 발생 인덱스를 추적하여 페이지 경계(`i % 999 == 998`)와의 일치 여부를 전수 조사함.
- **실측 결과**:
  - 전체 130개 파일에서 페이지 경계(`i % 999 == 998`)에 걸쳐 발생한 중복은 **0건 (None)**임.
  - 모든 중복은 단일 페이지 내부(`i = 2, 3` 등)에 나란히 인접하여 나타남.
  - 중복 레코드의 100%가 유찰(`dqlfctnRsn="유찰"`, `bidprcCorpBizrno=""`) 공고에 대해 KONEPS 데이터베이스가 복수의 유찰 사유 행을 기록한 원천 특성(Source Characteristic)임이 입증됨.
- **결론**: API 페이지네이션은 완벽히 안정적이며, 레코드 유실(Missing)이나 루프(Loop) 위험이 전혀 없음.
