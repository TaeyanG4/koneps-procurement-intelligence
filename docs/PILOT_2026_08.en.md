### 8.4 Temporal Foreign Key Tracking (`tender_in_scope`)

- `bidder_submissions`: August notice linked **1,569,500 rows (74.46%)**, prior notice linked **538,448 rows (25.54%)** [TEMPORAL_SCOPE_UNMATCHED]
- `award_outcomes`: August notice linked **12,918 rows (74.61%)**, prior notice linked **4,397 rows (25.39%)** [TEMPORAL_SCOPE_UNMATCHED]

- The `tender_in_scope: bool` flag explicitly tracks temporal membership, ensuring join safety for intra-month studies while preserving complete longitudinal integrity.

### 8.5 Privacy Boundary & Public Identity Policy
- Raw 10-digit business registration numbers (`bidprcCorpBizrno`, `fnlSucsfCorpBizrno`, `rprsntCorpBizrno`), representative/CEO names, telephone numbers, email addresses, and detailed street addresses have been completely purged from all 7 curated tables (verified by automated forbidden-column gate).
- **Public supplier identity is `supplier_id` only.** The previous `masked_biz_no` column (e.g. `123-45-*****`) has been removed from publishable curated output as there is no demonstrated analytical requirement for it in the public release.
- Company names (`supplier_name_ko`, `contractor_name_ko`, etc.) remain in curated tables as publicly available corporate trade names from KONEPS announcements. However, final privacy and licensing review is required before Kaggle publication.
- Supplier identities are pseudonymized via HMAC-SHA256 to `supplier_id` (`SUP_<32 hex>`).

### 8.6 Canonical Surrogate ID Serialization
- **Motivation**: The previous pipe-delimiter (`|`) string concatenation had a theoretical field-boundary ambiguity risk.
- **Current approach** (`CURATED_SCHEMA_VERSION = "1.1.0"`): Structured canonical JSON serialization (`entity`, `version`, explicit field names, explicit NULL sentinel `"__NULL__"`, sorted keys) guarantees that the same semantic row always produces the same ID regardless of input ordering.
- **Shuffle-invariance regression tests**: Verified automatically in `tests/test_curate_hardening.py` — shuffling input row order must not change the resulting ID set.

### 8.7 Dimension Snapshot Statistics (Explicit Namespacing)
- Aggregate statistics in `05_suppliers` (e.g. `total_bids_in_scope`) are time-window snapshots, not stable entity identity attributes.
- **All such columns now carry the `snapshot_` prefix**: `snapshot_total_bids_in_scope`, `snapshot_total_wins_in_scope`, `snapshot_total_contracts_in_scope`, `snapshot_total_contract_amount_krw`.
- These columns must NOT be used directly as leak-free historical ML features.

### 8.8 Deterministic Name Resolution
- When multiple names are observed for the same business registration number across feeds, the **most-frequent normalized name with lexicographic tie-break** policy is applied deterministically.
- Name conflict counts are recorded as aggregate metrics only (`name_conflict_count`); no per-record examples are included in public metrics.

### 8.9 Collector Error Sanitization
- The `error` field in attempt summary receipts stores only the exception class name (e.g. `"ValueError"`, `"RuntimeError"`).
- Full exception messages — which may contain service keys, request URLs, query parameters, or server response bodies — are never written to `page_receipts` JSONL.
- Regression test `tests/test_curate_hardening.py::TestSanitizedExceptionReceipts` verifies that a fake secret embedded in an exception message never appears in receipt files.
